一个ZIP包可以正常打开，解压出的目录结构却仍可能存在歧义。问题有时藏在路径中间：两个文件没有重名，它们的父目录却可能只差大小写。

[![ZIP目录逐层检查](/images/blog/zip-directory-path-validation/zip-directory-mindmap.svg)](/images/blog/zip-directory-path-validation/zip-directory-mindmap.svg)

## 1. 没有单独列出的目录，也会被创建

ZIP里的一个条目可以叫作`assets/config/app.json`，而不单独列出`assets`和`config`这两个目录。解压这个文件时，程序仍然需要准备它们。

这些由文件路径带出的目录，可以理解为隐式父目录。如果检查只处理压缩包明确列出的条目，就可能漏掉实际需要创建的目录。

## 2. 完整文件名不同，父目录仍可能冲突

例如，包里同时包含`Config/a.json`和`config/b.json`。两个完整路径不同，简单检查重复文件名时，两者都可能通过。

但在不区分大小写的文件系统上，`Config`和`config`可能落到同一个目录；在区分大小写的环境中，它们又可能分别存在。解压结果因此可能随运行环境改变。

希望保持一致目录布局的程序，需要明确自己的路径比较规则，并把检查延伸到每一级父目录。还要区分文件和目录，避免一个条目把某个位置当作文件，另一个条目又要求它成为目录。

## 3. 路径树也需要控制规模

把路径拆成目录树，逐级登记名称和类型，可以发现只比较完整文件名时漏掉的冲突。重复使用拼写相同的父目录，则应当能够正常处理。

登记目录树时，还需要考虑数量限制。一个压缩包即使只有少量文件，也可能通过很深的路径带出许多目录。只计算压缩包条目数，不能完整反映实际需要建立的文件和目录节点数量。

因此，资源限制也应覆盖隐式父目录，避免路径登记和目录创建的规模超出预期。

## 4. 拒绝异常输入后，还要检查留下了什么

验证时，可以准备包含大小写歧义、文件与目录冲突的压缩包，再准备共享同名父目录的正常包，分别检查拒绝和正常解压是否符合预期。

发现问题时，程序不应继续把安装登记为成功。拒绝之后，还要检查原有文件、配置和安装记录是否保持在预期状态，并验证修正输入后能否正常重试。

一个环境中的通过结果，只能说明已经覆盖的那组条件。支持其他系统时，还需要实际验证那些系统上的路径比较和解压行为。
